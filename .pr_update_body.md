## What changed

This PR brings the Reflex merge screen closer to parity with the old `Merge Models` tab.

- reorganized the Reflex merge page so the main section now focuses on `Model A/B/C`, `strategy`, `target strategy`, and `Velocity`
- moved the old advanced merge controls into a dedicated `Advanced Options` section
- added support for `MBW`, `LRV`, `Bake in VAE`, `Output Filename`, and `Lazy Load` in the Reflex workflow
- updated merge queue submission so tasks are labeled with the selected merge strategy
- aligned merge config generation with the old tab behavior so advanced-only fields are omitted unless advanced options are enabled
- added regression coverage for the merge config builder and Reflex merge state behavior

## Why

The task context for this branch was to move the existing `Merge Models` tab workflow into Reflex and cover model selection, strategy selection, target strategy, Velocity/LRV, advanced options, and queue submission.

Before this change, the Reflex merge page already existed, but it only covered a simplified subset of the old merge workflow. This PR closes that gap so the Reflex UI can handle the main merge flow with behavior that is much closer to the previous tab.

## Important implementation details

- the main `Merge` page at `/` remains the migration target; no new route was introduced
- advanced-only fields such as `MBW`, `left_right_velocity`, `bake_in_vae`, and explicit `output_name` are now only written into the merge config when advanced options are enabled
- when advanced options are disabled, the resolved output name falls back to the default auto-generated filename behavior
- queued merge tasks now use `Merge: {strategy}` as the task name for clearer queue visibility
- added state-level tests for output-name auto-generation/locking and queue submission behavior
- added builder-level tests to verify that advanced fields are included or omitted under the correct conditions
